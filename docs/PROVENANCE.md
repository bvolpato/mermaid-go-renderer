# Provenance

This document records where the code and data come from. Many Go packages port mermaid 12.2.0, its libraries, or parts of Chromium. The renderer also runs bundled KaTeX and ZenUML JavaScript and has an original Go PDF writer.

The companion documents are [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md), which has the copyright lines and the license texts, and [LICENSE-AUDIT.md](LICENSE-AUDIT.md), which has the findings of the audit.

Audit snapshot: the 2026-11-09 fix pass recorded counts at commit `c21c3ec`. Later KaTeX, ZenUML, and PDF additions are not included in those counts. Existing package counts below are historical; see "Feature implementations" for the newer sources. Run the count again before a release (see "How the counts were made").

## Words in this document

| Word | Meaning |
|---|---|
| ported | The Go file follows an upstream source file line by line. Its first comment is `// Ported from ...`. |
| follows | The Go code reproduces the behavior of upstream code and names the upstream functions in comments, but it is not a line by line translation of one file. |
| embedded | An upstream file is in the repository unchanged, and the Go code loads it. |
| generated | A script under `tools/reference` wrote the file from an upstream source. The first line is `// Code generated ... DO NOT EDIT.` |
| original | The file ports no upstream file. |
| the license of this repository | The MIT license. The file `LICENSE` in the root has its text. |

A mermaid path such as `diagrams/pie/pieDb.ts` is relative to `packages/mermaid/src` of the mermaid repository at version 12.2.0. A path that starts with `packages/parser/src` is in the same repository. A path such as `d3-shape/src/arc.js` is relative to the npm package of that name. A path that starts with `plugins/` is in the repository of Eclipse ELK at version 0.9.1.

### How the counts were made

```sh
find internal -name '*.go' -not -name '*_test.go' | wc -l
grep -rl "Ported from" internal --include='*.go' | grep -v _test.go | wc -l
```

The first comment of a file is the comment lines before the `package` clause. The split into the groups above came from a script that reads those lines of each file.

## Feature implementations

KaTeX math uses the embedded `dist/katex.mjs` from KaTeX 0.18.11 in `internal/katex/katexjs`. Its SHA-256 is `b53ef659acd792006f80e32a0fbe16d84668306b2a58ce7fce052121745d5032`. The Go package runs it in goja and calls it as mermaid does. The installed development package is KaTeX 0.18.10 and is separate from this embedded source. `internal/ru/katex.go` sends the generated MathML to the browser layout engine; sequence diagrams also have specialized label placement in `internal/diagrams/sequence/katex.go`. The KaTeX style sheet and font files used by the mermaid-cli page come from KaTeX 0.16.47 in `internal/webfonts/files/katex`.

The `PageMermaidCLI` page registers the ZenUML diagram plugin. `internal/config/zenuml.go` follows the detector in `@mermaid-js/mermaid-zenuml` 1.0.1. `internal/diagrams/zenuml` runs the embedded `@zenuml/core` 3.49.2 renderer in goja. `PagePlain` does not register this plugin. The bundle's terms are recorded in `internal/diagrams/zenuml/LICENSES.txt`.

PDF printing follows the page setup of mermaid-cli 12.0.0 and its print layout: `internal/mmdc/print.go` names Puppeteer 25.16.0 and Chromium 156 sources. `internal/raster` maps SVG content to vector drawing operations. `internal/pdf` is an original Go writer for ISO 32000-1 PDF files; it does not port an upstream writer. The public API is in `pdf.go`, and the CLI options are in `cmd/mmdg`.

The reference browser is Chromium 156.0.8078.4 (`browsers.json` of Playwright 1.64.1, and the user agent in `internal/purify/clobber_names.go`). Three headers in `internal/font` name Chromium 156.0.8078.80. The headers in `internal/raster` name the Skia branch `chrome/m156`, and the headers in `internal/font` name the Skia revision `aa789d9b`. `internal/js/crmath` names V8 15.6.75 and LLVM libc at revision `b8b28272d32b`.
